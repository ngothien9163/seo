## Task 1 — `utils/site_paths.py` (resolver thuần, stdlib, không network)

Hàm một-điểm-sinh-path, dùng cho cả 5 module hard-code + report + profile.

```

def site_data_dir() -> str      # data/<slug>/ — CHỈ khi đã tồn tại, ngược lại '' (tín hiệu chưa migrate)
def site_file(name) -> str      # data/<slug>/<name> nếu dir tồn tại, nếu không → ROOT/<name> (flat cũ)
def site_config(name) -> str    # config/<slug>/<name> nếu dir tồn tại, nếu không → config/<name>
def report_prefix() -> str      # '<slug>_' nếu multi-site đang bật (dir tồn tại) hoặc >1 site, ngược lại ''
```

## Task 2 — Re-point 5 hard-code sang resolver (không phá test hiện có)

Đổi **giá trị default** của hằng số module-level từ literal sang gọi resolver, giữ **tên biến** để
test hiện tại (`rt.HISTORY_FILE = TEST_FILE`, `gsc.DATA_FILE = ...`, `kw.KEYWORDS_FILE = ...`,
`rl.STATE_FILE = ...`) vẫn override được — code đọc biến global lúc chạy, không capture.

- `utils/rank_tracker.py:41` `HISTORY_FILE = site_paths.site_file("rank_history.json")`

Vấn đề import-freeze: các module này gán global tại import → giá trị chốt lúc import, nhưng QĐ B
fallback nghĩa là **tại import (chưa migrate)** nó trả đúng path cũ → đơn site không đổi. Khi
muốn per-site runtime (CLI `--site` đổi `cfg.TARGET_URL` sau import) thì cần gọi lại resolver
lúc đọc. → Đổi code đọc trong rank/gsc/rate/keywords từ dùng thẳng `HISTORY_FILE` sang
gọi `site_file(...)` nếu biến global chưa bị test override. Cơ chế: giữ global làm **cache/override
slot**; hàm `_resolve_<x>()` trả `HISTORY_FILE` nếu khác default, ngược lại tính lại. Kiểm
chứng bằng test: set `cfg.TARGET_URL` mới + đã có `data/<slug>/` → đọc ra folder mới.

**Test:** chạy lại nguyên 4 suite con `_quick_gsc/keyword/export/alert/scheduler_test.py` → tất cả

## Task 3 — `--migrate-multi-site` (NON-destructive, + `--dry-run`)

`utils/migrate_sites.py`:

```
def plan(current_target_url) -> list[(src, dst)]   # doi file flat → data/<slug>/ / config/<slug>/
def migrate(dry_run=False) -> int                  # copy (khong move/xoa), tra so file
```

- Đọc `cfg.TARGET_URL` → slug. Với mỗi flat-file tồn tại (`rank_history.json`, `gsc_history.json`,
  `session_state.json`, `config/keywords.json`, `config/backlinks.json`, `data/backlink_status.json`,
  `data/alerts_state.json`, `data/scheduler_state.json`): copy sang `data/<slug>/` (file state) /
  `config/<slug>/` (keywords, backlinks store). **Không xóa bản gốc.**
- Idempotent: đích đã tồn tại + cùng SHA256 → bỏ qua; khác hash → báo conflict, không đè.
- `--dry-run`: in bảng `src → dst` + SHA256, không ghi.
- `main.py`: branch `elif "--migrate-multi-site" in sys.argv` → gọi hàm, exit code = số lỗi; in nhắc
  "bản gốc vẫn còn — owner tự xóa sau khi xác nhận GUI/CLI đọc đúng folder per-site".

**Test (offline, temp dir):**
- dry-run không sinh file.
- migrate thật: src vẫn còn sau khi copy (non-destructive) + dst đủ nội dung + hash khớp.
- chạy 2 lần: không nhân bản (skip theo hash).
- conflict (dst khác nội dung) → không đè, trả mã lỗi, dst giữ nguyên bytes.

**Commit:** `feat: F10 --migrate-multi-site non-destructive (copy, khong xoa goc)`
